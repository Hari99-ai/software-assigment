# Daily Instagram product publishing

The importable n8n workflow schedules **one product at 10:00 Asia/Kolkata**. Its HTTP node calls the bundled worker, which implements Sheets selection, AI generation, hosting, validation, media-container creation/polling, publishing, Sheet updates, retries and persistent recovery. The workflow exports no API secrets.

Accounts required: Google Cloud/Sheets service account, Instagram professional account and Meta developer app, Groq, Cloudinary; optionally Hugging Face. For zero hosted image-generation spend, run your own AUTOMATIC1111 Stable Diffusion server with a licensed model and its `--api` option. Local generation still requires suitable hardware, disk and electricity. The hosted Hugging Face option consumes limited inference credits and fails when unavailable/exhausted; unlimited free daily image generation is not promised. [Hugging Face billing](https://huggingface.co/docs/inference-providers/pricing), [Groq limits](https://console.groq.com/docs/rate-limits), [Cloudinary upload API](https://cloudinary.com/documentation/image_upload_api_reference).

Setup:

1. Install Docker Desktop. Copy `.env.example` to `.env`; set separate random n8n encryption/worker tokens and provider configuration. Preserve the encryption key across container restarts.
2. Create a Google Cloud service account, enable Google Sheets API and store its key in `secrets/google.json` (ignored). Import `product-template.csv` into a sheet tab named Products, retaining exact A:M header order. Share only this sheet with the service-account email as editor. Set its ID in `.env`. Make scheduled dates plain `YYYY-MM-DD` strings and prices numeric INR strings. Product IDs must be unique. Replace the demonstration row with verified inventory; its 2099 date prevents accidental eligibility.
3. Configure Instagram as described below. Do not enable the schedule before validating your account and content. The worker uses **Instagram Login**, not Facebook Login.
4. Configure Groq and Cloudinary; select `IMAGE_PROVIDER=local` or `hf`. With local generation, start an existing AUTOMATIC1111 instance whose API is reachable at `LOCAL_IMAGE_URL`. The worker converts output to a 1080×1080 RGB JPEG. The original sheet image URL is reference data; the workflow generates its own illustration.
5. Run `docker compose up -d --build`. Open `http://localhost:5678` and complete n8n's local owner setup. Import `workflow.json`. Create an **HTTP Header Auth** credential named AquaPure worker Authorization header: header name `Authorization`, value `Bearer <WORKER_TOKEN>`. Select it on the HTTP node. The placeholder credential ID in JSON is not a real secret.
6. Execute Manual test once. It **publishes** if an eligible record and valid providers exist. Inspect the public post, generated content and Sheet status. Execute again to verify no duplicate. Activate the workflow after review. Keep Docker/host running; laptop sleep prevents scheduled execution.

Instagram configuration:

- Convert to an Instagram **Business or Creator** account. Personal accounts cannot use this publishing flow. Create a Meta developer app with Instagram API / Instagram Login and configure the app's valid OAuth redirect URI.
- Authorize the account with `instagram_business_basic` and `instagram_business_content_publish`. Use development-mode app roles/test accounts for your own testing; publishing for other users requires the applicable access level/app review. Do not mix Facebook Login scopes/tokens with the Instagram Login endpoints.
- Exchange the authorization code for a short-lived token, then exchange for a fresh long-lived Instagram token. Configure the Instagram professional account ID and token in the worker environment. See [Meta Instagram platform](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/) and the [Meta-maintained API collection](https://www.postman.com/meta/instagram/overview). Select a currently supported API version in `.env`; `v24.0` is a configurable starting value, not an assumption about every app's allowed version.
- Worker endpoints: `POST https://graph.instagram.com/{version}/{ig-user-id}/media` with public `image_url` and `caption`; `GET /{container-id}?fields=status_code` until FINISHED; `POST /{ig-user-id}/media_publish` with `creation_id`; `GET /{media-id}?fields=permalink`.
- The image must be reachable by Meta without cookies/login and remain available while processing. Worker uploads JPEG to Cloudinary and validates its public response. App/account/media publishing quotas still apply.
- Start with a newly issued long-lived token. The worker stores it in its private SQLite volume and refreshes via `GET https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token&access_token=...` after 30 days. Long-lived tokens generally require renewal before their validity window expires and cannot be renewed after expiry/revocation. If the account revokes access, reauthorize, update `.env` and remove/replace the `secrets` table's Instagram token row before restarting. Never put tokens into the workflow JSON or Git. Restrict journal backups: the journal now also holds the current token.

Recovery behavior:

- GET requests back off on temporary network/server/rate-limit errors. n8n retries failed worker calls; SQLite checkpoints prevent repeat publication. Failed pre-publish jobs resume, including on later days, before a fresh selection. One actual publication per calendar day is enforced by the journal.
- Journal states: selected → prepared → container_created → publishing → published. The publishing state is saved **before** the publish POST. If the process or network fails after intent is committed, outcome is uncertain; automatic republishing stops. Check Instagram/Meta for the container's publication result. If published, record its media ID/permalink and state=published in the journal, then rerun to heal Sheets. Reset to container_created only after establishing it did not publish. Do not discard the journal volume or run multiple publishers for the same sheet.
- A completed publication is recorded locally before writing Sheets. A later retry heals Sheet status without posting again. Error details are retained in `error_message`. Optional private ntfy topic sends a generic error alert without product data/tokens; this is disabled when its environment variable is blank.
- Invalid/missing data is recorded as failed and skipped; duplicate IDs fail the run. Containers explicitly reported EXPIRED before publishing are cleared for automatic recreation on retry. Unknown publish outcomes still require reconciliation. Back up volumes and retain the n8n encryption key.

Run local logic tests with `python -m pip install requests`, then `python -m unittest -v test_worker.py`. Full container/provider integration remains unverified until accounts and Docker are configured. The local tests never publish to Instagram.
